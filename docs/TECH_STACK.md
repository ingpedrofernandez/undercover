# Tech stack

- `backend/`: FastAPI, with SQLAlchemy Core over Supabase's Postgres, in the `undercover` schema, or SQLite for the tests. The same Core queries run on both. Every API operation has an `operation_id`, a one-line docstring and no optional inputs. Paying a claim is a separate operation that takes the amount. The backend enforces the claim states, the sign-off limit, the two tries on a claim and that nothing is decided or paid twice, so the rules hold whatever an agent does. It works out payouts with UnderCover's payout rules.
- `agent/`: two agents on OpenRouter. The queue agent, built with LangChain's `create_agent`, plans a run as a to-do list and hands each claim to the claim agent. LangChain's `ModelRetryMiddleware` and `ModelCallLimitMiddleware` retry its failed model calls and cap them, and our own middleware sends it back if it tries to finish with a waiting claim missed. The claim agent is a LangGraph `StateGraph` built by hand, in the style of `labs/week2day3.ipynb`: it works one claim, waits for a handler's sign-off with `interrupt()`, and pays through the backend. A `PostgresSaver` saves every step in Supabase with `durability="sync"`, so a stopped claim carries on from its last step. The agent's own FastAPI service carries a claim on as soon as the backend reports a sign-off. The agents reach claims, runs, their instructions, the policy wording and the claims manual only through the backend's API. It uses DeepSeek V4.1 Flash (`deepseek/deepseek-v4.1-flash`) with low reasoning effort by default, or the model in the environment variable `MODEL_NAME` if set, such as `openrouter/free`. It calls OpenRouter through `ChatDeepSeek` from `langchain-deepseek`, because `ChatOpenAI` drops the reasoning OpenRouter sends. `langchain-openrouter` would keep it too, but needs `openrouter` below 1.0, and the project uses 1.2.
- Tracing: Langfuse, with its Python SDK v5 and its LangChain `CallbackHandler`, traces every agent run. Each piece of work on a claim is a trace in the session `<claim id>:<thread id>`.
- `dashboard/`: React, Vite and TypeScript.
- `e2e/`: Playwright tests.
- `data/`: the business data the backend starts from. The agent never sees `data/evals/`, which holds the answer key.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. The OpenRouter key is `OPENROUTER_API_KEY` in `.env`, and Langfuse's are `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` and `LANGFUSE_BASE_URL`. Supabase's Postgres is `DATABASE_URL`, through its session pooler; each process uses at most 4 connections. The backend and the service get `.env` from `npm run dev`, and `uv run -m agent` loads it; the tests never do.
